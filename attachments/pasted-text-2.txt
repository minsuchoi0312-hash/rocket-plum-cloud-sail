### A. 방금 고친 6가지에서 생겼을 부작용 (회귀 버그)
1. **장수 명령 이중 전송 부작용:** `@PJL SET COPIES=n`과 `ESC & l n X`를 동시에 보내고 있어. `ESC & l n X`는 부수 묶음(Collate: 1-2, 1-2)이 아니라 낱장 반복(Uncollated: 1-1, 2-2)으로 동작하거나, 일부 기종에서 PJL과 곱해져 `n × n`장이 나오는 문제가 있어. 지금 코드가 `@PJL SET QTY` vs `COPIES` vs `ESC & l n X`를 어떻게 다루고 있는지 점검해 줘.
2. **72px 축소와 PCL5e 원점 불일치:** 캔버스를 `2336×3364`로 줄여 그린 뒤 `ESC & l 0 E`, `ESC * p 0 x 0 Y`로 보내고 있어. PCL5e 논리 페이지 원점과 물리 여백(약 71~72px)이 겹치면서 왼쪽·위로 치우치거나 오른쪽·아래쪽 여백이 2배로 남는 현상은 없는지 확인해 줘.
3. **가로 PDF 90도 자동 회전 방향과 양면 넘김 충돌:** `pageDrawPlan()`이 가로 페이지를 시계 방향(+90°)으로 돌리는지 반시계(-90°)로 돌리는지, 그리고 사용자가 양면(`긴 쪽 넘김` / `짧은 쪽 넘김`)을 골랐을 때 가로 문서가 뒤집혀서(거꾸로) 찍히는 문제는 없는지 확인해 줘.
4. **15초 `Promise.race` 타임아웃 뒤 USB 파이프 오염:** `transferOut`에 `Promise.race`만 걸면 타임아웃 시 JS만 빠져나오고 실제 WebUSB OUT 엔드포인트는 계속 걸려 있거나 멈춰(stalled) 있어. 타임아웃·취소 직후 `clearHalt("out")`, `releaseInterface`, `close` 같은 복구 절차가 있는지, 없으면 두 번째 인쇄 때 어떻게 터지는지 확인해 줘.
5. **열린 PDF 유지 시 빠른 쪽 넘김 경합(Race Condition):** 사용자가 `< 이전 / 다음 >`을 빠르게 연타할 때, 이전 `page.render()`가 끝나기 전에 같은 캔버스에 새 렌더를 시작하면 `pdfjs`가 에러를 내거나 엉뚱한 쪽이 덮어씌워져. `renderTask.cancel()`과 요청 번호(토큰) 가드가 제대로 있는지 확인해 줘.

### B. PCL5e · PJL · PDF Direct 프로토콜 급소
6. **TIFF PackBits(`ESC * b 2 M`) 인코더 경계 버그:** 직접 짠 PackBits 인코더에서 (a) 같은 바이트가 128바이트 넘게 반복될 때 분할, (b) 서로 다른 바이트가 128바이트 넘을 때 분할, (c) `0x80`(-128 NOOP) 미생성, (d) 마지막 1~2바이트 누락, (e) 2바이트 반복 처리 등이 표준과 100% 맞는지 코드를 한 줄씩 검산해 줘.
7. **완전 빈 페이지(백지 쪽)와 양면 어긋남:** PDF 중간에 완전히 하얀 빈 쪽이 있으면 모든 줄이 흰 줄 건너뛰기(`ESC * b n Y`)로 사라지고 래스터 데이터가 0바이트가 돼. 이 상태에서 `FF(0x0C)`만 오면 많은 복사기가 빈 페이지를 무시해 버려서 양면 인쇄 앞뒤가 통째로 밀려. 지금 코드는 빈 쪽을 어떻게 처리해?
8. **전송 중간 취소 시 바이너리 스트림 파괴:** `ESC * b <n> W <바이너리 n바이트>`를 4KB 청크로 쪼개 보내는 도중에 사용자가 취소를 눌렀을 때, 헤더를 보냈다고 바로 `ESC E` + `ESC%-12345X@PJL EOJ`를 보내면 복사기는 아직 남은 바이너리 `<n>`바이트를 기다리다가 종료 명령을 그림 데이터로 삼켜 버리고 멈춰. 이 문제 처리돼 있어?
9. **양면 홀수 쪽 × 2부 이상 인쇄 시 뒷면 침범:** 3쪽짜리 PDF를 양면으로 2부 인쇄할 때, 1부의 3쪽(앞면)을 찍은 뒤 2부의 1쪽이 그 뒷면에 찍혀 버리는 현상(빈 뒷면 패딩 누락)을 막는 처리가 있는지 확인해 줘.
10. **PDF Direct(`wrapPdfJob`)의 실기기 폭탄:** CMD에 `PDF`가 있다고 해서 암호 걸린 PDF, PDF 2.0, 초고해상도 스캔 PDF(30~100MB), 또는 옵션 보드가 없어 실제로는 PDF Direct를 거부하는 기종에 원본 PDF를 그대로 쏘면 어떻게 돼? 크기 제한이나 실패 시 폴백 안내가 있어?
11. **PJL 헤더 안전성 및 래스터 명령 세밀도:** `@PJL JOB` 줄에 한글·따옴표·개행이 들어갈 여지는 없는지, `ESC * r 0 A` 대신 커서 기준 `ESC * r 1 A`나 래스터 폭/높이 지정(`ESC * r <w> S`, `ESC * r <h> T`)이 빠져서 구형 기종에서 깨질 여지는 없는지 확인해 줘.

### C. 한국 사무실 PDF · 이미지 렌더링 급소
12. **한글 비임베디드 폰트 백지 출력(가장 치명적):** 한글(HWP)에서 PDF로 내보낸 문서, 국세청·은행·관공서 PDF는 CID 한글 폰트가 미내장된 경우가 많아. 지금 `pdf-doc.ts`의 `getDocument()`에 `cMapUrl`, `cMapPacked: true`, `standardFontDataUrl`이 설정되어 있고 빌드 결과물에도 로컬로 포함돼 있어? 없으면 한글 공문서가 백지로 나오는지 확인해 줘.
13. **PDF 도장·주석·전자서명·입력 양식(AcroForm) 누락:** 계약서 도장, 체크박스, 폼에 타이핑한 글자, PDF 주석이 `page.render()`에 포함되어 찍히는지(`annotationMode` 등) 확인해 줘.
14. **암호화된 PDF 처리:** (a) 열기 비밀번호가 걸린 PDF, (b) 비밀번호 없이 열리지만 편집·복사 제한(소유자 암호)이 걸린 한국 관공서/은행 PDF를 올렸을 때 `pdfjs` 미리보기, `pdf-lib`의 `slicePdf()`, USB 인쇄, PDF 저장이 각각 어디서 어떻게 터지는지 확인해 줘.
15. **투명 PNG 검은 배경 & 스마트폰 사진 EXIF/HEIC:** 투명 배경이 있는 PNG/WebP(도장, 로고, 스크린샷)를 `drawOfficePage`/`renderSheetCanvas`로 그릴 때 먼저 캔버스를 흰색(`#ffffff`)으로 채우는지(안 채우면 투명 영역이 시커멓게 인쇄됨), 그리고 아이폰/갤럭시 사진의 EXIF 회전이나 HEIC 파일 처리가 어떻게 되는지 확인해 줘.
16. **혼합 규격 PDF(한 문서 안에 A4 세로 + A3 가로 섞임):** 여러 쪽 PDF에서 1쪽은 세로 A4, 2쪽은 가로 A3처럼 쪽마다 크기와 방향이 다를 때 `pageDrawPlan()`과 미리보기, 인쇄 창이 쪽별로 제대로 대응하는지 확인해 줘.

### D. WebUSB · 사무용 복합기 하드웨어 통신 급소
17. **복합기 다중 인터페이스 및 IPP-over-USB 오선택:** 사무용 복합기는 USB 안에 스캐너, 팩스, 대용량 저장소, 단방향 프린터(`protocol=1`), 양방향 프린터(`protocol=2`), 1284.4(`protocol=3`), **IPP-over-USB(`protocol=4`)** 인터페이스를 동시에 가져. 지금 `discover.ts`가 어떤 기준으로 인터페이스와 `alternateSetting`을 고르는지, IPP-over-USB(`protocol=4`)에 PCL5e를 잘못 쏠 위험은 없는지 확인해 줘.
18. **`GET_DEVICE_ID`의 `wIndex` 스펙 준수 여부:** USB Printer Class 표준에서 `GET_DEVICE_ID`(`bRequest=0`)의 `wIndex`는 `(interfaceNumber << 8) | alternateSetting`이고 `wValue`는 `configurationIndex`야. 지금 `discover.ts`가 프린터가 0번이 아닌 1번·2번 인터페이스인 복합기에서도 `wIndex`를 규격대로 넘기고 있는지 확인해 줘.
19. **`transferOut` 부분 전송 및 상태(`stall`/`babble`) 무시:** `sendUsbBytes`에서 `device.transferOut()` 반환값의 `result.status !== "ok"`나 `result.bytesWritten < chunk.byteLength`를 검사하고 재전송/에러 처리하는지, 아니면 무조건 다 나간 걸로 가정하는지 확인해 줘.
20. **`CMD` 문자열 파싱 및 정규식 오탐:** `CMD:PCLXL,PJL`, `CMD:PCL3GUI`, `CMD:PCL6`, `CMD:SPL,PJL`, `CMD:PDF_SCAN` 같은 실제 기기 문자열이 들어왔을 때 PCL5나 PDF Direct로 오판될 정규식 구멍이 있는지 실제 정규식을 가져와서 테스트해 줘.
21. **USB 절전·화면 꺼짐·장치 리소스 누수:** `sessions` 맵에 열린 `USBDevice`가 계속 쌓이거나, `close()`/`releaseInterface()`를 안 해서 다른 탭이나 앱이 프린터를 못 쓰게 막는 경우, 또는 `connect` 이벤트(선 다시 꽂음) 미감지 문제가 있는지 확인해 줘.

### E. OS 인쇄 창 · 메모리 · PWA · 상태 꼬임 급소
22. **OS 인쇄 창 대용량 PDF 메모리 폭탄:** 50~100쪽 PDF를 와이파이(OS 인쇄 창)로 뽑을 때 `data:image/jpeg;base64,...` 문자열을 배열과 DOM `<img>`에 한꺼번에 몇백 MB씩 올리면서 갤럭시탭 크롬이 강제 종료될 위험이 얼마나 큰지, `Blob URL`이나 정리 시점은 어떻게 돼 있는지 확인해 줘.
23. **`window.print()` 후 정리 타이밍 & 사파리 `@page` 한계:** `printSheet()`가 `#print-root`와 `body.is-printing`을 언제 지우는지(모바일 크롬/사파리에서 `window.print()` 직후 바로 지우면 백지 출력), 그리고 사파리가 CSS named page(`page: a3`, `page: b5`)를 무시하는 문제에 대비가 돼 있는지 확인해 줘.
24. **긴 메모 오버플로우:** 사용자가 `간단 메모` 탭에 2~3페이지 분량의 긴 글이나 공백 없는 긴 URL을 붙여 넣었을 때, USB 인쇄·OS 인쇄·PDF 저장에서 1쪽 아래가 잘려 영구 소실되는지 아니면 여러 쪽으로 나뉘는지 확인해 줘.
25. **서비스워커(`public/sw.js`) 배포 충돌 및 오프라인 깨짐:** 새 버전을 배포했을 때 캐시된 구버전 HTML이 삭제된 동적 `import()` 청크(`pdfjs-dist`, `pdf-lib`, `pdf.worker`)를 요청해 앱이 하얗게 뻗을 가능성과, 오프라인 PWA 실행 시 동적 청크가 캐시에 없어서 PDF 탭이 고장 나는 문제를 점검해 줘.
26. **전송 중 UI 조작·스토리지 예외 경합:** (a) USB 전송 진행 중 사용자가 탭을 바꾸거나 새 파일을 올리거나 `바꾸기`를 누르면 상태가 꼬이는지, (b) `localStorage`가 막힌 브라우저(시크릿/보안 정책)나 용량 초과·손상된 JSON이 들어 있을 때 앱이 아예 안 뜨는지 확인해 줘.

### F. 예외 입력 · 프라이버시 · 카탈로그 · 테스트 사각지대
27. **악성/비정상 입력 처리:** `pageFrom > pageTo`, `0`, 음수, 빈칸, `999999`, 0바이트 파일, 확장자만 `.pdf`인 일반 텍스트 파일, 1억 화소 파노라마 사진 등을 넣었을 때 크래시나 무한 루프, NaN이 나는 지점을 전부 찾아 줘.
28. **사내 기밀 문서 잔존 및 메모리 누수:** 계약서·신분증 같은 민감한 파일을 열었다가 다른 파일로 바꾸거나 탭을 닫을 때, `URL.createObjectURL`, 캔버스 픽셀 버퍼, `pdfBytes`, `#print-root` 이미지가 메모리에 남거나 브라우저 캐시·스토리지에 저장되는 지점이 있는지 확인해 줘.
29. **카탈로그·드라이버 DB 오분류 및 무명 USB 장치:** 국내 사무실 복사기(신도리코·캐논·후지필름·리코·KM·교세라·삼성·HP) 중 이름만으로 잘못된 언어로 분류되거나, `MFG`/`MDL`이 비어 있고 `CMD`만 있는 USB 장치에서 어떻게 동작하는지 확인해 줘.
30. **현재 테스트 4개의 맹점:** 지금 통과한 단위 테스트 4개가 *검증하지 못하고 있는* 핵심 로직 목록을 전부 나열해 줘.

마지막에 30개 중 **[지금 당장 안 고치면 실제 사무실 첫 테스트에서 바로 사고 나는 Top 7]**만 추려서 순위표로 정리해 줘.
