지금부터 `office_print` 프로젝트 전체(Dart, Kotlin, AndroidManifest, Gradle, iOS Info.plist/Podfile/Runner)를 네가 직접 한 파일씩 끝까지 읽고, **아직 아무도 못 찾은 숨은 버그·크래시·실기기 출력 사고 요인**을 스스로 찾아내서 레드팀 감사 보고서를 작성해 줘.

[중요 규칙]
1. **코드는 절대 수정하지 마.** 이번 턴은 오직 분석과 결함 발굴만 수행해.
2. 이미 고친 항목(투명 배경 합성, Android 14 PendingIntent, USB 백그라운드 스레드, MulticastLock, TCP flush, R8 keep, ACTION_SEND 캐시, PopScope, 언어 확인 화면, iOS Podfile)을 반복하거나 "전반적으로 잘 되어 있다" 같은 칭찬·포장은 전부 빼.
3. 추측이나 일반론 금지. 반드시 실제 코드를 읽고 **파일명, 함수명, 실제 코드 로직**을 근거로 "어떤 입력·상황에서 정확히 어떻게 터지는지"를 증명해.
4. 문제가 진짜 없으면 억지로 지어내지 말고, 대신 놓치기 쉬운 아래 관점들을 끝까지 추적해서 실제 코드에 구멍이 있는지 확인해 줘.

[스스로 파고들어야 할 감사 관점]
- **갤럭시탭 실사용 환경:** 태블릿 가로/세로 화면 회전, 분할 화면·삼성 DeX, 앱 백그라운드 전환 시 상태 초기화·Wakelock/MulticastLock 누수·전송 끊김 여부
- **네트워크·mDNS 함정:** mDNS가 IPv6(`fe80::`) 주소나 중복 호스트를 돌려줄 때, IPP 631만 열려 있고 9100이 닫힌 복사기일 때, `@PJL INFO ID` 응답이 느리거나 잘려 들어올 때, 사내 와이파이 전환·끊김 시 소켓/UI 동작
- **USB 생명주기·취소 후 복구:** 취소 시 Kotlin에서 연결을 강제 `close()`한 직후 복사기가 미완료 PCL 스트림 때문에 다음 작업을 거부하거나, 앱이 재연결 없이 바로 다음 인쇄를 시도할 때 어떻게 되는지
- **PCL5e 바이트·렌더링 경계 오류:** `pdfrx`가 반환한 실제 픽셀 폭/높이와 `ESC * r <w> S`·`ESC * r <h> T`·8의 배수 바이트 정렬이 1px이라도 어긋나는지, 0바이트·손상된 PDF·초고해상도 사진·HEIC 공유 파일·소유자 암호(복사 금지) PDF가 들어올 때 어디서 뻗는지
- **메모리·동시성·상태 꼬임:** `Isolate.run`에 대용량 픽셀 버퍼를 넘길 때 복사 비용(메모리 2배 피크), 빠른 버튼 연타·파일 교체·공유 인텐트 중복 유입 시 경합(Race Condition), `SharedPreferences` 손상 데이터 처리
- **iOS 실제 빌드·실행 지뢰:** 맥(Xcode)에서 처음 `pod install` 및 빌드할 때 터질 수 있는 설정 누락, iOS에서 로컬 네트워크 권한을 사용자가 거부했을 때의 에러 안내, iOS 파일 선택(`file_picker`/임시 파일 접근 권한) 문제
- **UI/UX 막다른 길:** 초보 사용자가 화면에서 갇히거나, 에러가 났는데 원인 파악이 안 되거나, 진단 로그에 정작 필요한 정보가 빠져 있는 지점

[출력 형식]
발견한 모든 결함을 심각도순(`[치명]` → `[높음]` → `[보통]`)으로 번호를 매겨 정리해 줘.
각 항목은 반드시 아래 4줄로 작성해:
- **위치:** 파일명 / 함수명
- **코드 상 결함:** 현재 코드가 실제로 어떻게 짜여 있는지
- **터지는 시나리오:** 갤럭시탭·아이폰·복사기에서 실제로 벌어지는 증상
- **수정 시점 분류:** [실기기 테스트 전 필수 수정 / 테스트 후 개선]
